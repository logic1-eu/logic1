# all-diff2: unresolved Reduce memory failure

Recorded on 2026-11-06 from existing measurements and logs. No new computations
were performed for this note.

## Status

Both Redlog configurations failed with `not enough memory available` in the
600-second benchmark run on 2026-11-05. All four Cartesian configurations
timed out. No completed DNF result is known for this input.

The cause of the Redlog failures has not been investigated in isolation.
The message alone does not distinguish an allocation limit, exhaustion of
available memory, excessive intermediate growth, or a defect. No connection
to the sumcracker-14e crash or the gr2006 stack overflow has been established.
There is no verified fix.

A standalone Reduce input exists, but its validation stopped before the DNF
call. It is a prepared diagnostic input, not a confirmed standalone failure
reproducer. No comparison with a newer Reduce build has been performed.

## Latest benchmark evidence

The formal rerun on **2026-11-05** used Sage and the corrected Redlog wrapper,
with **two concurrent computations** and a **600-second limit per call**.
Each call ran in a fresh spawned worker, with one timed invocation and no
warmup. Startup, input loading, and result counting were outside timing;
startup and counting had separate 30-second guards. The timed call includes
the parent/worker pipe round trip.

Redlog off means `bnfsac=False, bnfsm=False`; Redlog on enables both switches.
The native configurations use `method="cartesian"` and the indicated
`Simplification` value. The three simplifying configurations use
`max_pair_checks=500`.

| Configuration | Result atoms | Seconds or outcome |
| --- | ---: | --- |
| Redlog off | unknown | insufficient memory; exit code 1 |
| Redlog on | unknown | insufficient memory; exit code 1 |
| NONE | unknown | 600* |
| FINAL | unknown | 600* |
| AFTER_STEP | unknown | 600* |
| DURING_STEP | unknown | 600* |

`600*` denotes a timeout at 600 seconds, not a completed computation time.
The Redlog errors occurred before that limit. Both captured outputs contain:

```text
+++ Fatal error not enough memory available - stopping
```

The wrapper reported `redcsl failed with exit code 1` in both cases. Thus
these are recorded failures of the Reduce subprocess, distinct from the
native DNF timeouts. No complete marked result was obtained.

The saved outer execution times were 322.171 seconds for Redlog off and
324.473 seconds for Redlog on. These include test-process overhead and are
**not benchmark DNF timings**; the successful-computation timing fields are
null. The two Redlog runs overlapped. Their failures do not isolate the
effect of concurrent memory demand, and peak memory was not measured for
these calls. No failing internal procedure or native stack was captured.

No Flint checks were performed. The benchmark used an explicit March-snapshot
PATH: an existing agent process had retained an older PATH even after fresh
shells selected the new installation. Verify the executable and banner before
a future comparison.

## Earlier observations

On **2026-11-04**, private Sage screening sought differences between the
syntactic results of FINAL, AFTER_STEP, and DURING_STEP. The allDiff2
construction exceeded the initial 90-second phase guard.

With a larger allowance, preprocessing reduced 594 to **585 atom occurrences
in 15.705 seconds**. FINAL construction and syntactic reduction did not
finish within the remainder of a total 300-second allowance. That screening
excluded final semantic subsumption and formula reconstruction; it was not
a full public DNF call.

AFTER_STEP and DURING_STEP were then tested independently through the public
DNF function, with `max_pair_checks=500` and the normal benchmark timing
protocol. Both full calls timed out at **300 seconds**. These outcomes do
not establish that the configurations would return equal results.

The table before the March-snapshot refresh recorded a Redlog-off error
and a Redlog-on timeout at 60 seconds. The refresh on **2026-11-05** timed
out at 60 seconds under both Redlog settings. Immediately before the
600-second rerun, NONE and FINAL also had 60-second timeouts; the two
recursive configurations retained their 300-second timeouts. Shorter
timeouts did not establish successful completion or exclude a later error.

## Standalone diagnostic input

[all-diff2.red](all-diff2.red) was generated on 2026-11-05
using `smtlib_inputs.load_input(...).as_redlog()` with Sage. It bypasses the
Python wrapper's transport and result conversion. The current file has
SHA-256:

```text
ab527f1ce2d47f31f17c7e964c033f2e476c39825e41cf80cc4e7ad06b52c039
```

It selects Redlog on, assigns the DNF without printing the full formula,
and then counts atoms:

```reduce
on rlbnfsac, rlbnfsm;
on time;
dnf_result := rldnf all_diff2$
off time;
rlatnum dnf_result;
```

Its comments explain how to select Redlog off for an independent run.
The file contains no `backtrace` or `gc` diagnostic switches and has no
built-in timeout. Its header gives `redcsl -w < all-diff2.red` as the direct
invocation from this directory.

Loading was verified with the March snapshot: 594 input atoms and 305
variables. Validation deliberately stopped before DNF. No standalone DNF
outcome or comparison of diagnostic switches, redirection, or wrapper use
is recorded for this case.
